# GSM-7 小写 ç 兼容修复

日期：2026-09-23。目标版本：v1.2.5。部署结果见同目录《v1.2.5修复与部署验收》。

## 问题与依据

此前 `internal/message/codec.go` 只将大写 `Ç`（U+00C7）映射到 GSM-7 `0x09`。小写 `ç`（U+00E7）被自动识别为 UCS-2，HTTP 提交的一条原本可用 GSM-7 表达的短信因此以 DCS8 发送，可能产生更多分片。

[Unicode 官方 GSM0338 映射](https://www.unicode.org/Public/MAPPINGS/ETSI/GSM0338.TXT) 明确列出 `0x09 → U+00E7`，并说明这是对 ETSI 大写映射的修正；不是“ETSI 在 1999 年正式修订成小写”。

## 最小修改

本项修复的生产代码仅在 `internal/message/codec.go` 初始化发送映射时增加：

```go
gsm7DefaultCodes['ç'] = 0x09
```

编码识别、自动分片判断、packed 和 unpacked 编码共用该映射，因此无需分别修改 HTTP、Dispatcher、Store 或 SMPP Provider。

| 范围 | 行为 |
|---|---|
| 新提交 HTTP 正文含 `ç`，其余字符都可用 GSM-7 表达 | 自动选择 GSM-7，SMPP DCS0；`ç` 占 1 septet |
| 原有大写 `Ç`、普通 `c` / `C` | 原有发送支持及码位保持不变 |
| 中文、emoji、NUL、反引号等非 GSM-7 字符 | 自动选择 UCS-2 的既有行为保持不变 |
| 分解形式 `c + U+0327` | 不做 Unicode 归一化，仍不作为单个 `ç` 处理 |
| 显式 UCS-2 / DCS8 | 保持原编码及大小写，不因新增映射降为 DCS0 |
| SMPP 原始 payload / DCS / UDH / SAR | 保持既有透传规则 |
| 接收端解码及 ASCII 兼容推断 | 保留旧行为，不在这次发送兼容修复中调整 |
| 存储、查询正文 | 保留客户原始 `ç`，不把业务正文改写为 `Ç` |
| 额度 | 继续按新受理短信计算出的分片数扣减；幂等重试不重复扣减 |

这两个 cedilla 字符在 GSM-7 中共用一个码位，线上字节无法保存大小写差别。最终手机显示小写或大写取决于终端、SMSC 的实现，不能仅凭 DR 成功保证显示形态。直接 GSM-7 解码仍保留旧大写映射；已有 SMPP ASCII 推断可能把单独 `0x09` 解释成制表符，这属于原有接收行为，原始字节透传没有被本次修改改变。

不引入 DCS3 自动兜底或新配置开关，不改路由、租户、TPS、额度事务、DR 状态机、重试和数据库结构。只在初始化时增加一个映射项，无新增网络/数据库调用、锁或运行时依赖。

此前已受理并保存为 `ucs2` 的 outbox 继续使用原编码，不重新切分、不回算历史额度；需要验证新行为时使用新的 `client_msg_id`。上一项租户线路信息屏蔽仍是独立修改，本项修复没有改动其逻辑。

## 可复现验收结果

使用用户报告的完整 136 字符正文（包含末尾小写 `ç`）通过本地 HTTP Handler、Dispatcher、Memory Store 和生产 `submit_sm` 编码器：

| 用例 | 修复后期望 |
|---|---|
| 原始 136 字符正文 | 145 septets，DCS0，1 个提交分片；原来自动 UCS-2 会按 67 个单元拆为 3 段 |
| 160 个 `ç` | DCS0，1 段 |
| 161 个 `ç` | DCS0，2 段，153 + 8 |
| 306 / 307 个 `ç` | 分别 2 / 3 段 |
| 158 个 `ç` 加 `€` | 160 septets，1 段；扩展字符仍占 2 septets |
| 159 个 `ç` 加 `€` | 161 septets，2 段 |
| 单独 `ç` 的 packed/unpacked 字节 | 均为 `09`，不是 `3f`（问号） |
| `çÇ` 的 packed/unpacked 字节 | 分别 `89 04` / `09 09` |
| 明确要求 DCS8 的 `ç` | DCS8，正文 `00 e7` |
| 重复相同 `client_msg_id` | 同一个网关 ID，不重复发送、扣日额 |
| 剩余 1 段额度 | 先前提交及幂等重试后仍可发 1 段，随后新提交返回 429 |
| 日额度耗尽后的原消息回执 | 继续正常处理并聚合到 DELIVRD；查询正文保持原样 |

测试覆盖 `packed/unpacked × udh/sar/payload` 的生产报文生成。`payload` 模式仍由上游处理长短信，一次提交和理论额度段数的既有差异不在此修复中改变。测试只生成本地报文，没有发送真实短信；HTTP 生命周期测试的回执通过本地队列处理，未连接外部回调接收端。

修复前运行新增字符及分片边界用例，已复现小写 `ç` 被识别为 UCS-2、160 个 `ç` 被分成 3 段的问题；修复后对应测试通过。环境验收仅使用已核实的测试桩线路，不向真实短信供应商发起测试。
