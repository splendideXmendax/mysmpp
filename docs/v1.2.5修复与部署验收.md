最初隔离容器限制为 0.5 CPU，旧清理用例在 15 秒维护预算内只完成部分数据，因此断言失败。保持生产代码不变、将临时测试容器限额调整为 2 CPU 后通过。这说明清理吞吐受资源影响，不代表已完成线上 200 TPS 压测。测试结束删除了临时容器，并核对所有原容器 ID 和启动时间未变。

## 接口兼容说明

HTTP 提交仍为 200。回调只发送整条最终结果，`segment_count` 保留，`segment_index` 移除，`state` 与 `message_state` 都表示整条状态，`final=true`。三个线路字段是移除而非置空。

同一最终通知仍可能因失败、应答丢失或进程重启重试，客户应返回任意 `2xx` 并按 `delivery_id` 去重。新版 ID 前缀为 `http-final:`；跨升级可按 `gateway_id + final` 兼容旧 ID。已发送的旧通知不能撤回，已完成的历史任务不主动重发。

HTTP pending 的 `dlr_delivered` 表示分片内部处理完成；客户最终通知完成状态以对应 `http-final:` 任务为准。旧程序不理解新快照标记，有未完成新任务时不得直接回退旧程序。
