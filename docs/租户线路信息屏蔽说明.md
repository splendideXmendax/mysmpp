# 租户线路信息屏蔽与 HTTP 最终回执

版本：v1.2.5。日期：2026-09-23。部署验收记录见同目录《v1.2.5修复与部署验收》。

## 修改结果

| 出口 | 变化 | 保留 |
|---|---|---|
| HTTP 提交及幂等重试 | 移除 `provider`、`provider_id`、`route` | HTTP 200、`gateway_id`、`state` |
| 租户消息查询 | 移除 `Provider`、`ProviderID`、`Route` | 其他字段名称、大小写及账号隔离 |
| HTTP DR | 移除线路字段、逐片序号和中间态；只通知整条最终结果 | 客户业务 ID、网关 ID、总分片数、最终状态、错误码和时间 |
| 租户错误响应 | 不返回包装错误中的线路或数据库详情 | 原有 HTTP 状态码和基础业务提示 |
| 管理员、CDR、数据库 | 保留线路信息和逐片记录 | 运维排障及 `(provider, provider_id)` 回执匹配 |
| SMPP DR | 本项不改报文、关联 ID 或发送逻辑 | 原有逐条提交的回执语义 |

鉴权成功后的账号上下文决定返回格式，伪造 `X-Client-ID` 不会取得管理员数据。管理员 Basic Auth 兼容模式仍只在未配置 `clients` 时成立。

## HTTP 最终回执示例

```json
{
  "delivery_id": "http-final:<opaque-gateway-fingerprint>",
  "gateway_id": "m0000abc",
  "client_msg_id": "order-001",
  "segment_count": 3,
  "state": "DELIVRD",
  "message_state": "DELIVRD",
  "final": true,
  "error_code": 0,
  "done_at": "2026-09-23T00:00:00Z",
  "callback_rule": "order-service"
}
```

`client_msg_id` 是客户提交的业务 ID；`segment_count` 保留同一网关消息的上游分片总数，不再通过 `segment_index` 表示某一分片。客户预切分 SMPP 消息有各自的网关 ID，本次不把它们跨请求合并。

所有分片都进入终态后才形成最终通知。全部成功才返回 `DELIVRD`；任意一片失败时按既有聚合优先级返回失败状态和对应错误码，不使用最后收到的分片状态覆盖整条结果。`done_at` 来自触发最终聚合的已保存回执事件，批量超时使用超时事件时间。既有 `submit_status` 可选数字字段保留。

## 持久化与去重边界

原逐片回执任务继续更新内部状态和 CDR。HTTP 的最终快照通过现有 `EnqueueReceipt` 插入独立通知任务，主键由全局唯一 `gateway_id` 派生，利用已有插入冲突去重。只有插入成功才能完成来源任务；通知独立使用现有租约、重试和持久化机制。

因此多个分片同时失败、批量到期以及升级前的多个最终快照，只形成一个对外任务。即使 pending 已被到期清理，完整快照仍能发送。不新增表、迁移、配置、Redis 或运行时依赖。

对于 HTTP，pending 的 `dlr_delivered` 表示该分片内部任务处理完成；确认客户最终通知是否成功，应检查 `receipt_jobs` 中对应 `http-final:` 任务的状态。每条带回调的最终消息多一个持久化任务，减少长短信的外部 HTTP 请求数；未进行 200 TPS 压测。

HTTP 无法保证网络绝对只请求一次：客户收到请求但应答丢失，或进程在 POST 成功后、任务确认前退出，都可能重试。相同任务 ID、正文保持稳定，客户返回任意 `2xx` 并按 `delivery_id` 幂等处理。

升级后未完成的旧任务使用新格式；已推送数据不能撤回。旧 `delivery:` 与新 `http-final:` ID 不同，跨升级可额外按 `gateway_id + final` 去重。已完成的历史通知不主动补发。旧版本不识别新聚合快照标记，不能在有未完成聚合任务时直接回退旧程序；应先排空或制定兼容回退方案。

## 修改边界与验证

生产修改限定在 HTTP 输出对象、HTTP DR 通知调度和回执快照的可选标记。`ReceiptDelivery.HTTPFinal` 对旧记录默认 false；已有 PostgreSQL NUL 文本封装同时保留该字段。发送编码的独立修复见《GSM7小写cedilla兼容说明》。

路由选择、长短信固定通道、租户鉴权、TPS、日额事务、outbox 防重复发送、上游回执入库以及 HTTP/HTTPS 地址安全策略均保持原机制。

回归覆盖：租户/管理员输出隔离、提交与幂等、HTTP/HTTPS、20 片并发与中间态抑制、混合成功失败、批量拒绝、缺片超时、pending 清理后通知、历史快照并发合并、File 重启与租约恢复、503 重试、正文 NUL、内部 CDR，以及独立 PostgreSQL 数据库上的同类测试。
